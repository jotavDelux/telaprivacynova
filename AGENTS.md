## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

- Render imported static profile markup in the TanStack home route, using the shared Button's original variant and scoped profile CSS to preserve the supplied design.
- Store supplied media as asset pointer JSON files; subscription buttons open the internal payment screen to retain the supplied design.
- Keep checkout plan IDs and prices in a shared browser-safe catalog; server functions validate plan IDs and derive prices rather than trusting browser amounts.
- NxGate runs through server functions and a signed public webhook, using private server-managed orders scoped to a random HttpOnly checkout session so guest orders never require public table access.
- Do not request payment credentials from chat or forms for this integration; absent server configuration must remain non-charging, and provider response bodies must not be logged because they may echo credentials.
